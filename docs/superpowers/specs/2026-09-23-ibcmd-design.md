# Группа команд `ibcmd`: сборка и обновление ИБ 1С без конфигуратора

Дата: 2026-09-23
Статус: согласовано, ожидает плана реализации

## 1. Цель

Дать в actions группу команд `ibcmd`, которая через утилиту ibcmd (без запуска конфигуратора 1cv8 DESIGNER) собирает и обновляет информационную базу 1С из исходников EDT, а также выполняет сопутствующие операции с ИБ.

Критерии успеха:

- Одной командой `ibcmd build` можно собрать/обновить файловую или серверную ИБ из проекта EDT (конфигурация или расширение).
- Перевод существующего конвейера с `infobase *` на `ibcmd *` сводится к замене имени группы и опций подключения.
- `--processpath` работает так же, как у остальных команд actions.
- Пароли не попадают в лог.
- Существующие команды (`infobase *`, `edt *`) не меняют поведения.

Вне рамок:

- Перевод CI-шаблонов `yml/*.yml` на ibcmd (отдельная задача после проверки).
- Режим автономного сервера (`ibsrv`, `--config=<yml>`).
- Импорт/экспорт отдельных объектов и файлов (`config import files`, `config export objects`).

## 2. Ключевые факты об ibcmd

- ibcmd не читает формат EDT. Шаг «EDT → XML» остаётся за 1cedtcli (`РаботаEDT.ЭкспортВXML1CEdtCli`), ibcmd заменяет только конфигуратор (`/LoadConfigFromFiles`, `/UpdateDBCfg` и т. п.).
- Серверная ИБ подключается напрямую к СУБД (`--dbms --db-server --db-name --db-user --db-pwd`), а не через кластер 1С.
- В 8.5 режим `config` вынесен на верхний уровень, но путь `infobase config ...` по-прежнему поддерживается. Используем `infobase config ...` — он работает на 8.3.20+ и 8.5.
- `infobase create` поддерживает `--import=<каталог XML> --apply`: создание ИБ из XML и обновление БД одним вызовом.
- В 8.5 у `config apply --session-terminate` нет значения `auto` (только `disable|prompt|force`).
- ibcmd использует каталог данных (`--data`) с файлом блокировки `lock.pid`; по умолчанию — общий каталог в профиле пользователя.

Минимальная поддерживаемая платформа: 8.3.20. Версия заранее не проверяется — на старой платформе ibcmd сам вернёт ошибку.

## 3. Решение по реализации

Собственный тонкий раннер `МенеджерIbcmd` на `КонтролируемыйПроцесс`. Путь к ibcmd находим через `v8find` (`Платформа1С.ПутьКIBCMD(МаскаВерсии)`), который уже есть в зависимостях.

Библиотеку ibcmdrunner не подключаем. Причины:

- она запускает процесс через `1commands.Команда`, поэтому `--processpath` с ней не работает;
- в ней есть ошибки: `ТестированиеИИсправление` всегда падает на `Ожидаем`; результат `СравнитьВерсии()` (-1/0/1) в пяти местах используется как Булево;
- строка запуска не логируется.

Библиотека используется как справочник по ключам ibcmd.

`packagedef` и `Dockerfile` не меняются.

## 4. Состав команд

Имена подкоманд повторяют группу `infobase`.

```
ibcmd                        Работа с ИБ 1С через утилиту ibcmd (без конфигуратора)
├─ build                     Сборка/обновление ИБ из проекта EDT (конфигурация или расширение)
├─ create                    Создать ИБ: пустую или из --template (cf | dt | каталог XML)
├─ configloadfromxml         XML → конфигурация ИБ + обновление БД (--noapply — без обновления)
├─ configsavetoxml           Конфигурация ИБ → XML
├─ configload                cf → ИБ + обновление БД (--noapply)
├─ configsave                ИБ → cf (--db — конфигурация БД вместо основной)
├─ configapply               Обновить конфигурацию БД
├─ configcheck               Проверка конфигурации
├─ dump                      ИБ → dt
├─ restore                   dt → ИБ (--createdb — создать БД при отсутствии)
└─ extension
   ├─ loadfromsrc            XML → расширение + обновление (--noapply)
   ├─ savetosrc              Расширение → XML
   ├─ load                   cfe → ИБ + обновление (--noapply)
   ├─ save                   Расширение → cfe
   ├─ update                 Обновить БД для расширения
   ├─ list                   Список расширений
   ├─ delete                 Удалить расширение (--name или --all)
   └─ properties             Изменить свойства расширения
```

### 4.1. Общие опции подключения

Есть у всех команд, работающих с ИБ.

| Опция | Назначение | ibcmd |
|---|---|---|
| `--dbpath` | Каталог файловой ИБ | `--db-path` |
| `--dbms` | Тип СУБД: MSSQLServer, PostgreSQL, IBMDB2, OracleDatabase | `--dbms` |
| `--dbserver` | Сервер СУБД | `--db-server` |
| `--dbname` | Имя БД на сервере СУБД | `--db-name` |
| `--dbuser` | Пользователь СУБД | `--db-user` |
| `--dbpassword` | Пароль пользователя СУБД | `--db-pwd` |
| `--user` | Пользователь ИБ | `--user` |
| `--password` | Пароль пользователя ИБ | `--password` |
| `--v8version` | Маска версии платформы для выбора ibcmd (`8.3.27`, `8.5`) | — |
| `--processpath` | Каталог контроля зависших процессов | — |
| `--data` | Каталог данных ibcmd. По умолчанию — временный на каждый запуск, удаляется после | `--data` |

Правила:

- Задано ровно одно из `--dbpath` или `--dbms`. Иначе — ошибка с понятным текстом.
- При `--dbms` обязательны `--dbserver` и `--dbname`.
- Значение `--dbms` проверяется по списку допустимых (без учёта регистра).
- Параметры авторизации ИБ (`--user`, `--password`) не передаются в `infobase create` (ИБ ещё не существует).
- Короткие синонимы опций не должны пересекаться внутри одной команды.

### 4.2. Опции команд

| Команда | Опции (кроме общих) |
|---|---|
| `build` | `--project` (обяз.), `--extension`, `--create`, `--path`, `--edtversion`, `--workspace`, `--dynamic`, `--sessionterminate` |
| `create` | `--template` (cf, dt или каталог XML), `--locale`, `--sqloffs`, `--noapply` |
| `configloadfromxml` | `--path` (обяз.), `--noapply`, `--dynamic`, `--sessionterminate` |
| `configsavetoxml` | `--path` (обяз.) |
| `configload` | `--file` (обяз.), `--noapply`, `--dynamic`, `--sessionterminate` |
| `configsave` | `--file` (обяз.), `--db` |
| `configapply` | `--dynamic`, `--sessionterminate` |
| `configcheck` | — |
| `dump` | `--file` (обяз.) |
| `restore` | `--file` (обяз.), `--createdb` |
| `extension loadfromsrc` | `--path` (обяз.), `--name` (обяз.), `--noapply`, `--dynamic`, `--sessionterminate` |
| `extension savetosrc` | `--name` (обяз.), `--path` (обяз.) |
| `extension load` | `--file` (обяз.), `--name` (обяз.), `--noapply`, `--dynamic`, `--sessionterminate` |
| `extension save` | `--name` (обяз.), `--file` (обяз.) |
| `extension update` | `--name` (обяз.), `--dynamic`, `--sessionterminate` |
| `extension list` | — |
| `extension delete` | `--name` или `--all` (ровно одно) |
| `extension properties` | `--name` (обяз.), `--active`, `--safemode`, `--securityprofile`, `--unsafeprotection`, `--usedindistributedib`, `--scope` (`infobase` \| `data-separation`) |

Булевы свойства в `extension properties` принимают `yes`/`no` (передаются в ibcmd как есть). Если свойство не задано — не передаётся.

`--dynamic` принимает `auto | disable | force`, `--sessionterminate` — `disable | force`. Значение `prompt` запрещено (в конвейере зависнет). Если опция не задана — ключ не передаётся, действует умолчание ibcmd.

`create --template`: тип определяется по пути — каталог → `--import`, `*.cf` → `--load`, `*.dt` → `--restore`. Иначе — ошибка. `--apply` добавляется для `--import` и `--load`, если не задан `--noapply`.

## 5. Архитектура

```
actions.os ──► Ibcmd.os (группа, как Edt.os)
                 ├─ IbcmdBuild.os ──────────► РаботаEDT.ЭкспортВXML1CEdtCli ─┐
                 ├─ IbcmdCreate.os, IbcmdConfig*.os, IbcmdDump/Restore.os     │
                 └─ IbcmdExtension.os ► IbcmdExtension*.os                   ▼
                          │  опции                                   МенеджерIbcmd.os
                          ▼                                                   │
                 РаботаIbcmd.os (модуль)                          КонтролируемыйПроцесс
                 ОписаниеКоманды / ПрочитатьПараметры                         │
                                                                         ibcmd(.exe)
```

### 5.1. `src/Модули/РаботаIbcmd.os`

По образцу `Работа1С.os`.

- Наборы опций: `КонструкторОбщий()` (подключение + авторизация + v8version + processpath + data), `КонструкторСоздания()` (без авторизации ИБ) и т. д.
- `ОписаниеКоманды(Команда, МассивПараметров)` — регистрирует опции из набора.
- `ПрочитатьПараметры(Команда, МассивПараметров)` → `Структура` с ключами `КаталогИБ`, `ТипСУБД`, `СерверСУБД`, `ИмяБД`, `ПользовательСУБД`, `ПарольСУБД`, `Пользователь`, `Пароль`, `ВерсияПлатформы`, `КаталогКонтроляОткрытыхПриложений`, `КаталогДанных`. Выполняет проверки из п. 4.1.
- `ПроверитьЗначениеИзСписка(Значение, Допустимые, ИмяОпции)` — для `--dynamic`, `--sessionterminate`, `--scope`, `--dbms`.
- `ПроверитьУстановкуIbcmd()` → Булево, для `doctor`.

Описания опций собственные: в `Работа1С` у `--dbserver`/`--dbname` справка ссылается на `--server`/`--ref`, что для ibcmd неверно.

### 5.2. `src/Классы/МенеджерIbcmd.os`

По образцу `МенеджерКонфигуратора.os`.

Публичный интерфейс:

- `Инициализация(Параметры)` — находит ibcmd по маске версии (ошибка, если не найден), формирует параметры подключения, создаёт временный каталог данных (если `--data` не задан).
- `Деструктор()` — удаляет временный каталог данных. Ошибки удаления пишутся в лог отладки и не прерывают работу.
- `СоздатьИБ(ПутьКШаблону = "", Обновить = Истина, Локаль = "", СмещениеДат = Неопределено)` — `Неопределено` означает «не передавать» (0 — допустимое смещение для MSSQL)
- `ЗагрузитьКонфигурациюИзXML(Каталог, ИмяРасширения = "")`
- `ВыгрузитьКонфигурациюВXML(Каталог, ИмяРасширения = "")`
- `ЗагрузитьКонфигурацию(ПутьКФайлу, ИмяРасширения = "")`
- `ВыгрузитьКонфигурацию(ПутьКФайлу, ИмяРасширения = "", КонфигурацияБД = Ложь)`
- `ОбновитьКонфигурациюБД(ИмяРасширения = "", ДинамическоеОбновление = "", ЗавершениеСеансов = "")`
- `ПроверитьКонфигурацию(ИмяРасширения = "")`
- `ВыгрузитьДанные(ПутьКФайлу)`
- `ЗагрузитьДанные(ПутьКФайлу, СоздатьБД = Ложь)`
- `СписокРасширений()` → Строка (вывод ibcmd)
- `УдалитьРасширение(ИмяРасширения)`, `УдалитьВсеРасширения()`
- `ИзменитьСвойстваРасширения(ИмяРасширения, Свойства)` — `Свойства`: Структура с заданными свойствами.
- `ВыводПоследнейКоманды()` → Строка

Приватная `ВыполнитьКоманду(Режим, Аргументы, САвторизацией = Истина)`:

1. Собирает параметры: `<режим> <подключение> --data=<каталог> [<авторизация>] <аргументы>`.
2. Пишет в лог (уровень Информация) строку запуска, в которой значения `--password`, `--db-pwd` заменены на `***`.
3. Запускает `КонтролируемыйПроцесс`: `УстановитьКаталогКонтроляОткрытыхПриложений`, кодировка вывода UTF-8, **без** исполнения через командную оболочку. `ВывестиСтрокуЗапуска()` не вызывается.
4. Ненулевой код возврата → исключение с текстом вывода ibcmd.

Пути с пробелами оборачиваются в кавычки. Пароли передаются аргументами напрямую: приём ibcmdrunner с `%ПЕРЕМЕННОЙ%` через `cmd /c` не скрывает пароль из списка процессов (оболочка раскрывает его до запуска ibcmd.exe) и ломается на `&`, `^`, `%`.

Перед реализацией проверить, не пишет ли `КонтролируемыйПроцесс` полную строку запуска в лог отладки. Если пишет — логировать через него нельзя, либо добавить в класс возможность отключить это.

## 6. Поведение `ibcmd build`

1. Проверить опции; каталог `--project` должен существовать. `--create` вместе с `--extension` — ошибка.
2. Каталог XML = `--path` или новый временный каталог. Каталог `--path` очищается (как в `edt cli export`), это указывается в справке опции.
3. `РаботаEDT.ЭкспортВXML1CEdtCli` (проект, каталог XML, `--workspace`, `--edtversion`, `--processpath`).
4. `МенеджерIbcmd.Инициализация`.
5. Далее:
   - `--create`: `infobase create --create-database --import=<xml> --apply --force`;
   - `--extension <имя>`: `infobase config import --extension=<имя> <xml>`, затем `infobase config apply --extension=<имя> --force [--dynamic] [--session-terminate]`;
   - иначе: `infobase config import <xml>`, затем `infobase config apply --force [--dynamic] [--session-terminate]`.
6. В любом исходе: `Деструктор`, удаление временного каталога XML (если `--path` не задан).

`--force` в `apply` передаётся всегда (конвейер не интерактивен).

### Риск: импорт отсутствующего расширения

Не проверено, создаёт ли `infobase config import --extension=X` расширение, если его нет в ИБ. Проверить первым шагом реализации. Если не создаёт — перед импортом, если расширения нет в `extension list`, вызывать `infobase config extension create --name=<имя> --name-prefix=<префикс>`, где префикс берётся из `NamePrefix` в `Configuration.xml` выгрузки.

## 7. Обработка ошибок

- Ошибка валидации опций → `ЗавершениеРаботыОшибка` до запуска ibcmd.
- ibcmd не найден для заданной маски → `ЗавершениеРаботыОшибка("Не найдена утилита ibcmd для версии платформы %1")`.
- Ненулевой код ibcmd → `ЗавершениеРаботыОшибка` с выводом ibcmd.
- Ошибка экспорта EDT — как сейчас в `ЭкспортВXML1CEdtCli`.
- Временные каталоги удаляются и при ошибке ibcmd. Исключение: при ошибке экспорта EDT `ЭкспортВXML1CEdtCli` сама завершает процесс, и временный каталог XML может остаться (он создаётся в каталоге временных файлов ОС). Существующую функцию ради этого не меняем.

## 8. Тестирование

Интеграционные тесты в `tests/tests.os` через `ЯВыполняюКомандуПродуктаCПередачейПараметров`.

Без платформы (выполняются всегда):

- `ibcmd` без аргументов → справка, код 0.
- `ibcmd configcheck --dbpath X --dbms PostgreSQL ...` → код 1.
- `ibcmd configcheck` без подключения → код 1.
- `ibcmd configapply --dbpath X --dynamic prompt` → код 1.

С платформой (под `ЭтоЛокальноеТестирование`), на временной файловой ИБ:

- `create` → `configsave` → `create --template <cf>` → `configsavetoxml` → `configloadfromxml` → `configapply` → `configcheck` → `dump` → `restore`.
- `extension loadfromsrc` (фикстура) → `extension list` (вывод содержит имя) → `extension properties --active no` → `extension savetosrc` → `extension save` → `extension delete --name` → `extension load` → `extension delete --all`.
- Маскировка: запуск с `--user Админ --password Секрет123` на ИБ без пользователей; в выводе нет `Секрет123` (код возврата не важен).

С EDT (если `РаботаEDT.ПроверитьУстановкуEdt()`):

- `build --create`, затем `build`, затем `build --extension` на фикстурах.

Фикстуры в `tests/fixtures/ibcmd/`:

- `edt-configuration/` — минимальный проект EDT конфигурации;
- `edt-extension/` — минимальный проект EDT расширения;
- `xml-extension/` — XML-выгрузка минимального расширения (сгенерировать ibcmd и закоммитить).

Серверные ИБ автотестами не покрываются — ручная проверка на стенде пользователя.
